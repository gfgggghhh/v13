# تقرير التطوير والتحقق – VeinFinderAndroid

> **ملخص صريح:** كل ما يخص المعالجة والتثبيت الزمني تم **تجميعه وتشغيله فعليًا** (Kotlin 1.9.24 + OpenCV Java على JVM) وقياسه.
> أما طبقة Android (CameraX/Camera2، الإعدادات، الواجهة) فقد **كُتبت وراجعتها لكن لم تُبنَ ولم تُجرَّب على جهاز** — انظر «ما لم يتم التحقق منه».

## 1) ما وجدته في الكود الأصلي
- `VeinProcessor.kt` **لا يحتوي CLAHE ولا Retinex كلاسيكي** كما ورد في الطلب. المراحل الفعلية: طرح Gaussian 191px (≈ single-scale Retinex)، قسمة على التباين المحلي **بدون حدّ أدنى للضوضاء**، Normalize بـ min/max عام، دالة عتبة (k,b)، ثم `equalizeHist` عام.
  min/max و`equalizeHist` تُحسب من جديد في كل إطار ← **وميض (flicker)**، والقسمة بلا حد أدنى ← **تضخيم ضوضاء**.
- **تسرّب ذاكرة native حقيقي**: `Mat.zeros(...)` داخل `absdiff` لا يُحرَّر + أي استثناء يترك Mats. قياس: **1.19 MB لكل إطار** (≈3.5 GB بعد 3000 إطار).
- كل إطار ينشئ Bitmapين جديدين (ضغط GC).
- الملف `Vin` هو في الحقيقة GitHub workflow، ولا يوجد `gradlew` (فكان الـ CI سيفشل). سجل `hs_err` = انهيار Gradle بسبب ذاكرة 3GB (خفّضت `-Xmx` إلى 1536m).

## 2) ما تم تنفيذه
| المجال | التنفيذ |
|---|---|
| المعالجة | مسار جديد على مرحلتين `flatten` ثم `render`: Retinex لوغاريتمي مع قناع للوهج/الخلفية، تطبيع تباين محلي **بحد أدنى للضوضاء**، Bilateral خفيف، تعزيز خطوط رفيعة (Hessian متعدد المقياس **مع كبت الحواف** لمنع خطوط الظل الوهمية)، منحنى نغمات ناعم بإحصاءات ممهَّدة زمنيًا (لا وميض)، وCLAHE في Medium/High. **الخوارزمية الأصلية محفوظة كمستوى Legacy وتطابق الأصل بت-ببت (60/60 صورة).** الصورة الأصلية لا تُعدَّل أبدًا. |
| المستويات | Legacy / Low / Medium / High + Contrast + Noise reduction + زر **Compare** يحفظ نفس الإطار بكل المستويات. |
| التثبيت الزمني | LK optical flow + RANSAC (تحويل تشابهي) ← محاذاة ← دمج تكراري بوزن لكل بكسل (بوابة أشباح) ← **رفض** الحركة الكبيرة/غير الموثوقة (يُعرض الإطار الحالي كما هو) ← تخميد اهتزاز العرض بحد أقصى صغير. لا تأخير (لا يوجد buffer). تشغيل/إيقاف + Strength. |
| الكاميرا | Resolution، Frame rate، Exposure lock، AWB lock، Focus lock، EV، Manual exposure/ISO، Manual focus عبر Camera2 interop — **كل عنصر يُفحص مقابل إمكانيات الكاميرا الفعلية** ويظهر معطَّلًا مع السبب إن لم يُدعَم. زر «Camera report» (اضغط سطر الـFPS). |
| الواجهة | Display: Original / Enhanced / Stabilized، شاشة إعدادات واحدة، حفظ/استعادة كل القيم (نفس ملف prefs القديم فتبقى k,b). Save يحفظ الأصل PNG + المعالَج. |

| الذاكرة | `MatScope` (تحرير مضمون)، Bitmap ring، عدّاد native heap على الشاشة. |

## 3) نتائج القياس (حقيقية، لكن على بيانات مرجعية ليست صور هاتف)
بيانات: صور NIR حقيقية لظهر اليد (dataset عام) **+ تدهور محاكى** (تدرج إضاءة، ظل، وهج، ضوضاء shot+read)، و phantom بحقيقة أرضية دقيقة (أوردة رفيعة 1.5–2.5px، حافة ظل حادة، وهج).
**AUC** = قدرة إظهار الأوردة (أعلى أفضل). على الحقيقة الدقيقة (phantom، ضوضاء n4 / n10):

| المستوى | AUC كل | AUC **رفيعة** | ضوضاء HF نسبية (أقل أفضل) | تسرب حافة الظل/وريد |
|---|---|---|---|---|
| Legacy (الأصل) | 0.857 / 0.816 | 0.815 / 0.770 | 0.476 / 0.571 | 0.048 / 0.061 |
| Low | 0.853 / 0.813 | 0.788 / 0.739 | **0.240 / 0.275** | 0.067 / 0.086 |
| **Medium** | 0.887 / 0.858 | 0.853 / 0.809 | 0.364 / 0.408 | 0.061 / 0.054 |
| High | **0.896 / 0.872** | **0.868 / 0.827** | 0.423 / 0.474 | 0.048 / 0.046 |

على الصور الحقيقية (حقيقة أرضية تقريبية، ضوضاء+إضاءة): Legacy 0.850 → Medium 0.881 → High 0.886 (AUC)، والضوضاء 0.170 → 0.086 → 0.103.
**تنبيه:** Low يتنازل عن بعض حساسية الأوردة الرفيعة مقابل أقل ضوضاء (مقصود)، والحقيقة الأرضية للصور الحقيقية مشتقة من Frangi فقد تميل قليلًا لصالح تعزيز الخطوط.
اكتشاف مهم أثناء الضبط: الإعداد الأول كان **يخسر الأوردة الرفيعة مقارنة بالأصل** (بسبب تشبّع منحنى النغمات)، فعُدِّل — لذلك القيم الحالية نتجت عن اختبار لا عن تخمين.

**التثبيت الزمني** (تسلسلات من صور حقيقية بحركة معروفة، Strength=60 مقابل Enhanced بلا تثبيت):
| الحالة | النتيجة |
|---|---|
| ثابت | ضوضاء زمنية **7.46 → 3.70 (−50%)** بلا خسارة AUC |
| ارتعاش يد | AUC نفسه (0.906→0.905)؛ مؤشر الأشباح 0.369→0.402 (**زيادة طفيفة**) |
| انجراف بطيء | AUC 0.912→0.909 (لا تأخير ملحوظ) |
| قفزة سريعة | رُفض 8% من الإطارات، **لا أشباح** |
| اهتزاز عنيف مستمر | **45% مرفوضة**، AUC والأشباح كما بدون تثبيت (قبل الإصلاح كان AUC 0.75 وأشباح ×300) |
أثر «تخميد اهتزاز العرض» صغير جدًا في المحاكاة (لم أستطع قياسه بثقة)؛ الفائدة الرئيسية هي خفض الضوضاء.

**الأداء (JVM، نواة واحدة بمستوى سطح المكتب – وليس الهاتف):** الأصل ≈20ms، Enhanced ≈31ms، Stabilized ≈45–50ms للإطار 640×480.
**الذاكرة:** الأصل 1.19MB/إطار تسرّب؛ الجديد ≈0 (3000 إطار: +20–35MB إجمالًا، متباطئ = تخزين مؤقت للمخصِّص). 96 تشغيلًا على مدخلات شاذة (أسود/أبيض/ضوضاء/أحجام صغيرة وفردية) بلا أي فشل، والإطار المُدخَل لا يتغير.
**اختبارات وحدة:** 13 اختبارًا (منطق الكاميرا/الإعدادات/العدّادات) ناجحة.

## 4) ما لم يتم التحقق منه (مهم)
1. **لم يُبنَ المشروع بـ Gradle ولا Debug/Release** (لا Android SDK ولا مستودعات Google في بيئتي). ملفات `MainActivity/PhoneCameraSource/SettingsDialog` تعتمد على AndroidX/CameraX ولم يمكن فحصها بالمترجم. أضفت workflow يشغّل الاختبارات + Debug + Release على GitHub — **أول بناء قد يُظهر أخطاء ترجمة صغيرة** في هذه الملفات.
2. **لم أجرِّب على POCO M6 Pro**: لا أعرف ما تدعمه كاميراته فعليًا (Manual sensor/Focus). CameraX قد يتجاوز بعض مفاتيح AE/AF على بعض الأجهزة. استخدم «Camera report». لم تُختبر كل الدقّات المدعومة على الجهاز، ولا FPS/المعالج الحقيقي (السطر الأخضر يعرضها حيًا).
3. الاختبارات على **صور NIR وتدهور محاكى** وليس صور أوردة بكاميرا الهاتف بالضوء المرئي؛ القيم (شدة الخطوط، عتبة الرفض 2% من العرض، …) **مبدئية** حتى تُقارن على لقطاتك: استخدم زر Compare وأدوات `tools/bench` على صورك وفيديوهاتك المرجعية.
4. **المستوى الافتراضي صار Medium** (كان الأصل فقط). اختر Legacy في أي وقت للمقارنة. في وضع Stabilized مع Legacy يُستخدم Medium.
5. كاميرات USB (UVC): دُعمت الدقّة فقط؛ تحكم التعريض/التركيز غير موصول، وواجهة مكتبة UVC لم أستطع التحقق منها (كما في الأصل).
6. لا توجد اختبارات سابقة في المشروع لأشغّلها.
7. بيانات الـdataset العامة استُخدمت للتقييم المحلي فقط ولم تُضمَّن.
